# TEOF Patterns

Validated patterns extracted from observation. These emerge from applying TEOF across domains and are designed to be universally applicable.

---

## Structure

| File | Domain | Description |
|------|--------|-------------|
| **structural.md** | Universal | Patterns about how systems are structured |
| **operational.md** | Universal | Patterns about how to operate effectively |
| **metaphysical.md** | Universal | Patterns about the nature of observation and reality |

---

## How Patterns Work

Each pattern includes:

- **H-Level:** Position in the hierarchy (H1-H10)
- **Domain:** Where the pattern applies
- **Statement:** The pattern itself
- **Validation:** How it was verified
- **Key insight:** The core takeaway
- **Related:** Links to other patterns

---

## The Hierarchy (H-Levels)

| Level | Name | Function |
|-------|------|----------|
| H1 | Unity | Coherence of the whole |
| H2 | Energy | Resource acquisition and flow |
| H3 | Direction | Propagation, influence, spread |
| H4 | Defense | Boundary maintenance, protection |
| H5 | Intelligence | Processing, learning, adaptation |
| H6 | Truth | Verification, accuracy, honesty |
| H7 | Power | Control, leverage, influence |
| H8 | Ethics | Coordination, reciprocity |
| H9 | Freedom | Optionality, sovereignty |
| H10 | Meaning | Purpose, significance |

---

## Using Patterns

1. **Diagnose** — Evaluate a system against the hierarchy. Where are the gaps?
2. **Apply** — Use relevant patterns to address identified weaknesses.
3. **Validate** — Test whether the pattern holds in your specific context.
4. **Extend** — If you discover new patterns, document them with the same structure.

---

## Contributing

Patterns are validated observations. To propose a new pattern:

1. State the pattern clearly
2. Provide evidence/reasoning
3. Link to existing patterns if relevant
4. Submit for review

Patterns that survive scrutiny get integrated. Patterns that contradict existing validated patterns trigger revision.
