# Seed: Public Blank Slate

This folder is a minimal starter scaffold for people who want to use TEOF as the seed of their own personal or project system.

The intent is simple:

- keep public doctrine public
- keep personal state local
- let real use refine your own periphery

---

## What This Folder Is For

The public repo gives you the core.

This `seed/` folder gives you a clean place to begin building your own:

- identity model
- direction / priorities
- observations
- projects
- local patterns

without leaking those back into public canon by default.

---

## Recommended Pattern

Use the repo in three layers:

1. **Core**
   - `core/TEOF-core.md`
   - `core/layers/L1 principles.md`
   - `core/TEOF.md`

2. **Seed / Translation**
   - your personal identity and direction
   - your diagnostic notes
   - your domain-specific adaptations

3. **Periphery / Execution**
   - projects
   - workflows
   - automation
   - logs and observations

The rule is:

**private state should stay in your own working system until it has proved broadly reusable.**

---

## Suggested Local Files

| File | Purpose |
|------|---------|
| `identity.md` | Who you are, what is load-bearing, what patterns keep recurring |
| `direction.md` | What matters now, active goals, constraints, current bottlenecks |
| `observations.md` | Raw but useful observations that have not yet become doctrine |
| `projects.md` | Current build surface |
| `patterns.md` | Local patterns that may later earn promotion |

Template starting points are included here as `.template.md` files.

---

## Promotion Rule

When something emerges in your personal system, ask:

1. Is this only true for me?
2. Is it domain-specific rather than general?
3. Has it survived real application?
4. Would it still make sense without my private context?

If the answer to (4) is no, it should stay local.

If the answer to (4) is yes, and it survived contact with reality, it may be eligible for promotion into public notes, patterns, or canon.

---

## Safe Starting Move

1. Read `core/TEOF-core.md`
2. Read `core/layers/L1 principles.md`
3. Fill in:
   - `identity.template.md`
   - `direction.template.md`
   - `observations.template.md`
4. Start using the system on a real decision or project
5. Update only from actual observation, not from wanting the system to sound complete

That last point matters. A good seed grows by contact with reality, not by decorative completion.
